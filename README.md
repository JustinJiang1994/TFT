# 阵容罗盘 · 金铲铲 / TFT 对局助手

把版本阵容数据整理成可以在对局中使用的中文工具：**根据已有棋子、海克斯和转职，查看当前怎么过渡、升人口后补什么，以及最终阵容如何出装。**

项目英文名：**JCC / TFT Compass**；建议仓库名：`jcc-tft-compass`（远端当前仍为 `TFT`）。

项目包含离线攻略手册、独立对局助手和版本更新脚本。每次更新重新获取来源榜单，筛选当期全部 S/A 阵容并构建关联，不固定沿用上一版的21套阵容。

## 快速开始

1. 下载仓库：在 GitHub 点击 **Code → Download ZIP**，解压整个目录；也可以运行：

   ```sh
   git clone git@github.com:JustinJiang1994/TFT.git
   cd TFT
   ```

2. 用 Chrome、Edge 或 Safari 打开根目录的 **`index.html`** 选择金铲铲或TFT，再进入对应版本手册和助手。
3. 阅读和筛选不需要安装 Python、Node 或启动服务器；更新数据时才需要开发环境。

页面内嵌样式、脚本和数据，可离线使用。原始来源、历史版本和页面间跳转需要保留仓库目录结构。GitHub 文件预览和部分文件预览器不会执行交互脚本，请下载后使用正常浏览器打开。

**首页提供两个平台入口，当前金铲铲助手使用金铲铲数据。** 两个平台的补丁编号、平衡调整、统计人群和来源字段不能直接视为相同；阵容强度、装备评级和强化推荐分别维护，不用 TFT 数据填补金铲铲的缺项。

上表表示仓库快照，不保证实时反映游戏最新版本。当前发布指针见 [金铲铲版本清单](games/jcc/releases.json)和[TFT版本清单](games/tft/releases.json)。现有自动采集流水线接入金铲铲来源；TFT 保留历史资料，尚未接入同一套自动更新命令。

## 对局时怎么用

### 1. 先了解版本

手册第一章对比同来源的前后补丁：哪些阵容进入或退出 S/A、哪些均名发生变化，以及当期选中阵容的物理/法系和运营路线分布。装备统计帮助判断哪些装备可用于更多候选阵容。

### 2. 输入手上的条件

进入独立助手，选择当前等级和已有棋子，再按需要勾选转职、海克斯与装备方向。

- **棋子可以多选**，换等级保留选择；取消勾选或点击“清空棋子”才移除。
- **海克斯多选取交集**，只列当期阵容有推荐关联的强化。
- **必需转职未满足**的阵容单列为待补条件，不冒充当前已满足的推荐。
- 左侧条件区和右侧结果区分别滚动，避免反复在长页面上下查找。

选择保存在当前浏览器的本地存储中，按平台、赛季和补丁区分；不上传、不跨设备同步。浏览器限制本地存储或清理数据后，选择可能无法保留。

### 3. 分别看“现在怎么过渡”和“以后怎么补”

| 模块 | 匹配规则 | 你会看到什么 |
| --- | --- | --- |
| 当前过渡 | 当前等级中，同时包含所选棋子的已收录棋盘 | 还缺哪些棋子，以及该完整棋盘关联的全部终局阵容 |
| 后续补牌 | 独立查询目标等级，同时包含所选棋子的记录 | 潜在方向、缺少棋子的出现频率，以及完整补位方案 |

例如，当前4级没有某个终局的匹配记录，但6级记录包含你选中的两张棋子，这个方向仍可出现在6级后续候选中，不会被当前等级的结果排除。

继续勾选“已经补到”的棋子后，助手会重新计算剩余兼容组合与缺牌频次，不会把互不兼容的高频棋子拼成一套虚构阵容。暂不保留的打工棋子需要手动取消选择；零匹配只表示返回记录中未找到，不代表游戏中无法转型。

### 4. 查看成型与装备

点击阵容进入详细攻略，查看职责、目标星级、终局保留核心、运营建议、装备和强化。装备先满足主C与主坦，再考虑副C等其他承装位。

装备补全支持同名装备多件，区分 **S/A统计组合** 和 **来源推荐三件套**；先按 S、A 排序，同评级按均名升序。来源推荐但未达到 S/A 的出装不会被改标为 S/A。

## 数据口径

本项目区分来源事实、来源推荐与自行归纳，具体限制随快照记录。

- **分析范围**：版本定调与关联使用当期入选集合；来源完整榜单用于确定入选和退出。S/A遵循来源评级，不是本项目重新打分。
- **版本对比**：按同平台阵容ID及棋盘、主C、星级、入场条件核对；定义发生变化时不直接计算可比差值。样本不足1,000会提示，均名变化不等于补丁造成的因果效果。
- **核心与职责**：“终局保留核心”是已收录终局棋盘的交集，不保证所有打法都不可替换。主C/副C优先采用来源标记，主坦候选依据承装推定；运营节点属于建议时明确说明。
- **补牌频率**：按兼容组合中棋子的出现次数统计，不代表胜率、抽牌概率或独立对局数量。不同等级的记录不是同一局的连续升级轨迹。
- **装备泛用性**：当前按非挂件棋子的来源推荐出装，统计覆盖阵容数及装备件数，重复两件计两次；不等于必做顺序。
- **神器**：仅列有携带关联的条目；出现过不等于推荐使用或达到 S/A。

本次金铲铲快照完成233次请求，整理出285组分等级棋盘。来源未公开段位和统计时间窗；推荐强化最多返回10项，每等级棋盘通常只返回3组，棋子三件套存在200条返回上限。**完整保存返回记录，不等于穷尽游戏内全部组合。**

本次可用 S/A 三件套较少，因此单独保留来源推荐出装。无法映射的装备ID `6079` 已归档，不作为推荐选项。详细覆盖、缺失字段与限制见各快照的 `manifest.json` 和页面“数据与来源”。

## 更新版本

在仓库根目录执行。需要 Python 3（采集与生成仅使用标准库）、网络连接；Node.js 用于匹配逻辑测试。

### 获取并预览

```sh
# 自动识别金铲铲来源的最新赛季和补丁
python3 scripts/knowledge/refresh.py

# 或明确指定来源版本
python3 scripts/knowledge/refresh.py --set 18 --patch 18.3
```

流程为：**完整抓榜 → 重新选择 S/A → 获取各阵容详情与词库 → 构建关联 → 校验 → 生成预览**。命令会输出快照与预览位置，打开对应 `games/jcc/set18/补丁/snapshots/时间戳/pages/guide.html` 和同目录的 `assistant.html` 检查。

### 发布为当前入口

```sh
# 将占位路径替换为刚生成的实际快照目录
python3 scripts/knowledge/refresh.py --snapshot games/jcc/set18/18.3/snapshots/NEW_TIMESTAMP/data --publish
```

发布更新平台版本清单、平台当前入口和根目录导航；内容页与数据同放在对应平台、赛季、补丁和快照下。每次抓取创建新时间戳；已发布快照拒绝覆盖。同一补丁重新更新，也应创建新快照。

采集失败会阻止发布，不会拿旧版数据补齐。`--publish` 只发布到本地项目，不会自动提交 Git、部署网站或创建定时更新任务。

### 检查交付

```sh
python3 scripts/validate_release.py
node scripts/knowledge/test_engine.cjs
node --check templates/knowledge-ui.js
```

当前已完成数据、链接、脚本语法与匹配逻辑检查，尚未通过浏览器视觉验收。发布前还应实际检查选择保留、条件筛选、当前/目标等级切换、补牌与装备补全。

## 项目结构

```text
TFT/                              本地目录名称，暂不改动
├── index.html                    平台选择首页
├── versions.html                 两个平台的版本入口
├── games/
│   ├── jcc/                      金铲铲
│   │   ├── index.html            本平台版本列表
│   │   ├── current.html          当前手册快捷入口
│   │   ├── assistant.html        当前助手快捷入口
│   │   ├── releases.json         本平台发布清单与当前指针
│   │   └── set18/18.3/
│   │       ├── snapshots/20261013T083011Z/
│   │       │   ├── pages/        guide.html、assistant.html
│   │       │   └── data/         manifest、knowledge、raw
│   │       └── research/         本版本早期核查资料
│   └── tft/                      TFT，与金铲铲完全分开
│       ├── index.html / current.html / assistant.html
│       ├── releases.json
│       └── set18/18.4b/
│           ├── index.html / assistant.html / equipment.html
│           ├── data/             该版阵容与装备来源
│           └── research/         该版刷新核查资料
├── docs/research/                跨平台对照说明与迁移前核查记录
├── docs/migration-paths.json     原路径 → 新路径对照
├── scripts/knowledge/            共用采集、生成、入口维护脚本
├── scripts/validate_release.py   文件、链接与发布清单检查
├── templates/                    共用页面样式与匹配引擎
├── skills/metatft-guide/         可复用Skill与流程模板
└── downloads/                   Skill压缩包
```

根目录旧页面名和旧 `releases/` 页面仅保留轻量跳转，兼容已有书签；实际内容归入平台及版本目录。历史原始响应不改写，内部记录的旧路径可通过迁移对照表定位。TFT18.4b保留原历史资料组织；后续新采集版本按与金铲铲相同的快照结构保存。

维护新版页面时修改 `templates/` 和生成脚本；直接编辑生成的 HTML 会在下次生成时被覆盖。修改可复用流程后，同步 Skill 中的 `assets/version-pipeline/` 与下载包。

离线分享可发送完整仓库压缩包；在线分享可将整个目录部署到静态站点服务，例如 GitHub Pages。项目无需后端、数据库或运行时 API 请求。部署应保留 `games/`、`docs/` 与兼容跳转页面，确保原始证据和版本链接可用。
