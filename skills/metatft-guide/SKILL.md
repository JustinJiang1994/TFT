# MetaTFT 中文攻略与定阵地图

把版本证据整理成玩家能在对局中查找的中文攻略。延续用户现有 HTML 时，先检查现有内容与数据，保留用户已经确认的模块和链接，不重建成只有概览的缩水版本。

## 工作入口

- 调研或换版本：读 [数据与证据](references/research.md)。先确认赛季、补丁、模式、段位和时间窗，再获取完整阵容集合与详情。
- 制作或修改网页：读 [交互结构](references/interface.md)。优先修改当前文件；需要从零开始时可参考 `assets/historical-reference.html` 的页面结构。
- 整理关联、反向索引或验证：读 [数据契约](references/data.md)，使用 `scripts/build_indexes.py`。

历史资产是 **2026-10-12 / TFT Set18 / 18.4b** 的设计样例，不是当前版本事实。它保留示例数据以供理解完整交互。不要把换标题、日期当成完成新版本更新，也不要直接运行旧项目中串联的补丁脚本：它们可能从备份重建网页，覆盖后续改动。

- 神器适配与神器定阵：读 [神器证据与候选树](references/artifacts.md)，使用 `scripts/build_artifact_index.py` 从棋子携带记录构建双向索引。

- 非挂件棋子的 S/A 装备与出装：读 [装备评级口径](references/equipment.md)，区分单件、重复件与三件套，按阵容分支整理。

## 完整性要求

用户要求全部时，所有章节按来源实际返回记录完整列出：不固定每套海克斯数量、不截取神器前几项、不只取第一个人口变体或少数开局。长列表用默认折叠、搜索与分组解决，而不是删除数据。左侧章节与阵容索引常驻展开。

每次更新记录来源数、页面数、未映射ID与缺失字段。海克斯全池逐阵容审计数据标记来源参考、机制建议、未证实；阵容页面仅展示推荐清单；全局海克斯树和筛选列表仅展示所选强势阵容推荐清单的并集，去掉无推荐关系的条目，完整矩阵保留在来源JSON。没有证据不能冒充适配。接口可能自带返回上限，要明确“完整返回数据”不等于游戏内所有组合。将海克斯/神器/转职反向树与交互筛选同步到同一完整数据源。

## 页面顶部的版本定调

在主标题后、工具和阵容索引前，概括物理与法系、赌牌比例、速8与速9方向、升级与搜牌窗口、强势体系，并提供左侧章节入口。用用户指定阵容集合内的同版本、同筛选记录计算路线占比，不混入集合外样本；物理/法系若只分析所选S/A，必须明确子集边界。记录数量不是独立对局数，运营标签不是结算等级；不可用幸存到9级的名次证明上9的因果收益。将统计节点与建议搜牌时间区分，展示快照日期及可折叠的计算依据，不凭少量头部阵容断言某流派普遍碾压。

## 必须保持的区别

1. **覆盖范围**：默认榜与条件阵容分别计数。用户说全部 S/A 时，核对完整列表，不只取前几条。阵容数量和评级阈值须随版本验证，不固定为21套。
2. **中文名称与版本**：使用该赛季中文词库；同名英雄、不同费用野怪、海克斯带“+”变体分别核对。TFT 与金铲铲国服不自动等同。
3. **事实与建议**：评级、升级节点、阵容样本、高手攻略及自行归纳分别标注。没有搜牌回合统计时，可给建议窗口，但不可称网站实测。
4. **核心棋子**：若用户定义为“不会被换下”，按所列人口变体的交集列出，并说明适用范围；不能把常见样本交集说成所有打法永久不可换。
5. **海克斯**：名称、银/金/棱彩、出现回合按词库核对。空统计字段不等于没有推荐；检查内嵌高手攻略的强化 tierlist。近似攻略等级不是当前分支胜率排名。
6. **定阵候选树**：方向是“已有条件 → 可选阵容”，例如护卫转 → 对应分支、物理装备 → 多套候选。不要替换成每套阵容五项检查清单。
7. **可摇摆不等于可直接转型**：共享海克斯是推荐适配关系；开局到终局是过渡样本关系。交集是候选，不是成功率。已经投入追三星的路线不能无成本转到其他终局。

## 完成交付

- 静态中文内容与可选列表写入 HTML，交互增强使用内嵌脚本，保证无网络也能阅读。
- 数量、链接、反向映射及脚本语法检查通过；条件允许时按可用浏览器技能验证交互，无法验证时准确说明范围。
- 修改前保留明确命名的备份；不把备份作为每次生成的默认输入。输出一个当前主页面及对应来源目录。
- 分享本地文件时给不带锚点的主页面链接。若预览器不执行 JavaScript，提示使用正常浏览器。分享、部署是独立需求；创建本技能不代表要求发布网站。

## 当前手册范围

当前项目仅分析已选21套强势阵容，不能额外引入别的阵容或全榜样本来做版本定调。转职定阵只保留这21套玩法的必需或可选条件，不展示“偶然出现即列入”的全转职记录；其他阵容的近似攻略不能独立作为本阵容推荐理由，必须核对玩法适用性。新版本阵容集合由用户指定范围确定。
